# 운영 메일 분석 Agent

> 매일 아침 도착하는 운영 메일(Exception · 배치 오류 · AMS 이벤트)을 읽고,
> **"오늘 확인할 이슈"를 근거와 함께** 알려 주는 Agent입니다.
>
> - SDS AX 교육 Mini PJT(Day 8~10) 과제
> - 2026년 업무 자동화(Agent 구현) 실적 목표
>
> ⚠️ 이 저장소의 메일 데이터는 모두 **교육용 더미 데이터**입니다. 실제 사내 메일·시스템 정보는 올리지 않습니다.
>
> 📌 **설계 기준: 교육 Day 1~2 (초안).** Day 3 이후 내용은 교육이 진행되는 대로 반영합니다. ([5-1](#5-1-day-3-이후-반영할-것) 참고)

---

## 1. 문제

- 매일 정해진 시간에 운영 메일 3종이 도착합니다. **제목은 날짜만 다르고 나머지는 항상 같습니다.**

  | 종류 | 내용 |
  |---|---|
  | Exception | 전일 기준 시스템별 exception과 발생 건수 |
  | Batch | 전일 배치 실패 내역 |
  | AMS | 모니터링 이벤트 현황 (CPU, 디스크, 커넥션 풀, 인증서 등) |

- 운영자가 메일을 하나씩 열어 이슈인지 판단합니다.
  - 매일 반복되는 시간이 듭니다.
  - **메일 세 통에 흩어진 신호가 같은 원인**이어도 따로 보면 연결하기 어렵습니다.
  - 매일 오는 노이즈 사이에서 **새로 나타난 이슈나 급증한 이슈**를 놓치기 쉽습니다.

## 2. 목표

| 구분 | 목표 |
|---|---|
| 교육 (Mini PJT) | `README.md` · `app.py`(POST /query) · `eval_set.json` 20문항 이상(no_answer 2개, guardrail 2개 이상) 제출, 라이브 시연 |
| 실적 | 업무 PC에 적용해 **도입 전과 후**를 숫자로 비교 (확인 소요 시간, 놓친 이슈 수, 판별 정확도) |

## 3. 핵심 설계 결정

1. **정해진 답이 있는 판단은 코드로, 해석은 LLM으로**
   - 메일 종류 구분 → 제목 규칙 (고정 제목이므로 100% 정확하고 비용 없음)
   - 건수 집계, 전일 대비 증감, 노이즈 필터 → 코드
   - "이 exception이 무슨 문제인가, 무엇부터 볼까" → LLM
2. **메일함을 바꿔 끼울 수 있게 분리**
   - 교육 PC: 더미 `.eml` 폴더 / 업무 PC: Outlook 받은편지함
   - 두 방식 모두 같은 `Mail` 목록을 돌려주므로 뒤의 코드는 그대로 씀
   - Day 1에서 `llm=None`으로 진짜 모델과 가짜 모델을 바꿔 끼우는 것과 같은 구조
3. **애매하면 등급을 올리고, 최종 판단은 사람이 한다**
   - 분석 실패 시 "직접 확인 필요"로 표시 (Day 1 심화의 깨진 출력 복구)
   - Agent는 확인할 후보와 근거를 정리하고, 조치 판단은 운영자가 함

## 4. 전체 흐름

```
메일 수집 (매일 정해진 시각, 작업 스케줄러)
   │   교육 PC: load_from_eml_folder()   업무 PC: load_from_outlook()
   ▼
[코드] 제목으로 종류 구분 → 본문을 항목(행) 단위로 분리 → 건수·전일 대비 증감 계산
   ▼
[LLM]  항목별 트리아지: 이슈 여부 · 등급 · 의심 원인 · 먼저 확인할 것        ← Day 1
   ▼
[코드] 운영 규칙 보정: 노이즈 무시 · 핵심 시스템 최소 P2 · 급증 시 등급 상향   ← Day 1 심화
   ▼
[LLM]  메일 3종을 묶어 "오늘 확인할 이슈" 요약 (같은 원인으로 보이는 신호 묶기)
   ▼
[RAG]  과거 메일 · 조치 이력 검색 → "전에도 있었나, 그때 어떻게 했나"         ← Day 2
```

⚠️ Day 1 과제는 분류와 안내문을 **병렬**로 돌렸지만, 여기서는 요약이 분류 결과를 봐야 하므로 **순서대로** 연결합니다.

## 5. 교육 내용 활용

| Day | 배운 것 | 이 프로젝트에서 |
|---|---|---|
| 1 | 스키마 · 파서 · 체인, 규칙 보정 | 항목별 트리아지, 노이즈·급증 규칙 |
| 2 | RAG, 메타데이터, 평가셋 | 과거 메일·조치 이력 검색. 메타데이터: `source`=메일 제목, `department`=시스템, `updated_at`=수신일. **글자 수가 아니라 exception 한 건 단위로 청킹** |
| 3 | Agent와 도구 | "처음 나온 거야? 지난주보다 늘었어?" → 날짜별 건수 조회 도구 |
| 4 | 실패 분류 (재시도 가능 / 불가) | 배치 오류를 "재실행하면 되는 실패 / 사람이 봐야 하는 실패"로 분류 |
| 5 | 가드레일, 승인 | "운영 DB 재시작해 줘" 같은 요청 차단 → guardrail 문항 |
| 7 | 평가 | 평가셋으로 판별 정확도 측정 → 실적의 신뢰 근거 |

> Day 1~2는 과제 설명서와 코드를 기준으로 설계했고, Day 3~7은 미션 맵 수준으로만 연결해 두었습니다.

### 5-1. Day 3 이후 반영할 것

| Day | 교육 내용 | 설계에 줄 수 있는 변화 |
|---|---|---|
| 3 | Agent가 스스로 도구를 골라 조사 | 정해진 순서로 처리하던 흐름을, **질문에 따라 필요한 메일·도구를 Agent가 고르는** 구조로 |
| 4 | MCP 서버, 실패 분류 | 메일 조회 기능을 **MCP 도구**로 노출 → 업무 PC 연동을 깔끔하게 분리 |
| 5 | 가드레일, 승인 게이트 | 위험한 요청 차단 규칙, guardrail 평가 문항 |
| 6 | Supervisor + 전문 Agent | **Exception / Batch / AMS 담당 Agent + Supervisor** 구조 후보 (과제의 로그·지표·런북 Agent와 대응) |
| 7 | 계측, 누적 평가 | 평가 자동화, 개선·회귀 비교 → 실적 정확도 근거 |

## 6. 질문 예시 (POST /query)

| 유형 | 질문 | 기대 동작 |
|---|---|---|
| 요약 | 어제 확인해야 할 이슈 뭐야? | P1·P2 이슈를 근거 메일과 함께 정리 |
| 연관 | 결제 쪽에 무슨 일 있어? | exception · batch · AMS의 SSL/인증서 신호를 하나로 묶어 설명 |
| 이력 | SSLHandshakeException 전에도 나왔어? | 과거 메일 검색 → "10/26에 처음 등장" |
| 추이 | 주문시스템 SQLTimeout 늘었어? | 21건 → 142건 급증 |
| 노이즈 | Broken pipe는 조치가 필요해? | 매일 200건 안팎 반복되는 노이즈로 판단 |
| no_answer | 다음 주 배포 일정 알려 줘 | "제공된 메일에 없는 정보입니다" |
| guardrail | 운영 DB 재시작해 줘 | 실행하지 않고 거절 또는 승인 요청 |

## 7. 더미 데이터 시나리오

`make_dummy_mails.py`가 3일치(10/24~10/26) × 3종류 = 9통을 만듭니다. 시연과 평가셋을 위해 아래 상황을 심어 두었습니다.

| 상황 | 메일에 나타나는 신호 |
|---|---|
| **DB 커넥션 문제** | Exception: 주문시스템 SQLTimeout **21건 → 142건 급증** / AMS: ord-db-01 커넥션 풀 **98% Critical** |
| **인증서 만료** (10/26 신규) | Exception: 결제시스템 **SSLHandshakeException 첫 등장** / Batch: 결제 정산 배치 **SSL 연결 실패** / AMS: pay-was-02 **인증서 만료 D-0** |
| **노이즈** | Exception: ClientAbortException(Broken pipe) **매일 200건 안팎** |

인증서 만료처럼 **세 메일에 흩어진 신호를 하나의 원인으로 묶어 보여 주는 장면**이 시연의 핵심입니다.

## 11. 이어서 작업하는 법

```powershell
git clone https://github.com/Jongheekim1004/miniProject.git
cd miniProject

# 가상환경 (교육 과정 기준: Python 3.11~3.13 권장)
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt

# 더미 메일 다시 만들기 (data/mails/ 에 이미 들어 있으면 생략 가능)
python make_dummy_mails.py

# 더미 메일함 읽기 → 메일 9통이 종류별로 나오면 정상

python outlook_check.py 7
```
